# Retrospective

## What worked

- A behavior-based contract reached independent audits, reviews, verifications,
  evaluations, Filing CI, and equivalent quality-control stages without
  converting authorized drafting self-checks into read-only work.
- Repeating the compact contract in each affected public skill preserved the
  boundary when a skill is installed without repository-root governance.
- Fresh-agent pressure testing found instruction-following failures that exact
  prose checks could not prove.
- The existing governance validator provided one CI-reachable enforcement seam
  without adding another tool or dependency.

## Misses and corrections

- The first launcher test accidentally embedded unescaped newlines in its
  synthetic reviewer. Correcting the fixture made the reviewer perform the
  intended artifact and extra-output writes before the launcher rejected them.
- The first GREEN contract did not defeat deadline, sunk-cost, claimed-approval,
  and contrary-workflow rationalizations. A focused RED rule and a corrected
  hybrid audit instruction closed that gap; the next three fresh agents
  preserved all canonical hashes.
- The first behavior classifier favored current frontmatter sentence forms.
  Public-CLI tests added arbitrary skill names and noun, gerund, and direct
  `performs` forms while retaining drafting-from-report and internal-self-check
  negative controls.
- Exact inverse strings did not catch a coexisting paraphrased edit permission.
  Bounded modal and mutation-verb checks now reject the tested same-stage
  permissions.
- Unreadable `SKILL.md` entrypoints initially failed open. Validation now emits
  a stable skill-specific error.

## Boundary retained

The change adds no general audit/remediation engine. Independent quality control
can report complete proposed language, but only a separately authorized drafting
or revision stage may implement it. A later fresh read-only stage verifies the
new version.

## Future rule

When a new public skill independently assesses an artifact, give its frontmatter
an explicit quality-control trigger and include the install-local contract. Add
new validator grammar only through a failing arbitrary-name public-CLI test.
