# Proposal: Generic Judicial Reasoning Profile Builder

## Why

Issue #33 must remove the embedded real-judge skill and establish one generic,
folder-native builder before the shared judicial-reviewer launcher is created.

## What changes

- Add `building-judicial-reasoning-profiles` with an install-local folder
  contract, domain schema, validator, immutable-package reference, fictional
  fixtures, and UI metadata.
- Define separate acquisition and compilation operations. Acquisition output
  cannot be consumed until a later validated invocation.
- Add deterministic source-class, attribution, cross-class comparison, neutral
  transfer, and prohibited-field validation.
- Route the builder through the shared immutable folder-package loader and
  publisher without adding a repository or case-management dependency.
- Remove `drafting-for-judge-scholer` and every public README, router, guide,
  test, example, governance, and active-spec dependency on that package.
- Preserve the generic judge-overlay receipt processor until downstream Issue
  #61 migrates it to the shared static-role launcher.

## Capabilities

### New capability

- `building-judicial-reasoning-profiles`

### Modified capabilities

- `judge-overlay-authoring`
- `implemented-skill-folder-migration`
- `repository-skill-governance`

## Non-goals

- No real-judge conclusion or fixture.
- No outcome prediction, voice imitation, assignment manipulation, or perceived-
  preference exploitation.
- No judicial-reviewer launcher, sweep, or person-specific agent identity.
- No generated skills, CaseGraph, Git, registry, or mutable package access.
