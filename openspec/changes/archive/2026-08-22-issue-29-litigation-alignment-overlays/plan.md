# Implementation Plan

## Objective

Deliver a public, test-backed litigation-alignment overlay skill and shared
lifecycle method that transforms one immutable docket snapshot into role-
separated, source-backed, versioned review inputs without researching counsel or
editing a filing.

## Task 1: Public structure RED

Add one focused structure test for the exact public skill package, its three
install-local schemas and validator, general guide, README/router routes,
judge-guide lifecycle link, and non-placeholder durable Purpose. Prove RED is
caused only by absent Issue 29 artifacts.

## Task 2: Validator and lifecycle RED

Create generic synthetic in-test builders and committed public fixtures for:

- a complete complaint-to-motion-to-amendment-to-recommendation-to-order
  snapshot and overlay;
- a no-responsive-filing overlay with two blind jobs;
- a current filing-version manifest; and
- bounded invalid mutations.

Exercise the validator through its public CLI and direct stable findings. Lock
down individual preservation, issue-scoped splitting, municipality separation,
explicit overrides, attack/response/treatment vocabularies, magistrate/district/
appellate authorship, derived source unions, silence degradation, blind/actual
slices, four jobs per group, and stale/failing manifests.

## Task 3: Minimal public skill and schemas

Add `skills/building-litigation-alignment-overlays/` with `SKILL.md`,
`agents/openai.yaml`, three reference schemas, one standard-library validator,
and generic fixtures. Keep schemas concrete and validator findings stable. Add
no dependency or unrelated helper.

## Task 4: Lifecycle documentation and routing

Add root `OVERLAYS.md` as the shared owner. Update README and
`section-1983-drafting` to route overlay creation and consumption. Link
`JUDGE_OVERLAYS.md` to the shared lifecycle and define judge-specific triggers.
Do not duplicate counsel-specific lifecycle or research rules before Issue 30.

## Task 5: GREEN and pressure

Run focused tests until GREEN, then use the complete generic lifecycle and
no-responsive-filing fixture as fresh skill pressure. Run quick skill
validation, discovery, all unit/evaluation tests, OpenSpec, corpus, governance,
formatting, forbidden-folder and comment searches, and diff checks. Commit and
sync.

## Task 6: Whole review and archive

Inspect all role boundaries, linked-record semantics, fingerprints, grouping and
review-plan invariants, lifecycle language, public safety, and scope. Capture
accepted Critical or Important findings as RED before correction. Complete
verification and retrospective records, archive with the repository-local CLI,
replace the durable judge-overlay placeholder Purpose, rerun full validation,
commit, sync, and preserve the worktree for the Issue 30 child.
