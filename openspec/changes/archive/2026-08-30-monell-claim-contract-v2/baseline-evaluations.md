# Baseline Evaluations

These read-only scenarios ran against committed production skills at
`6a0216a10a5d9c22a5737f772cc78b9313da0a1d`. Evaluators were told not to read
this OpenSpec change.

## Complaint contract and checker

The evaluator correctly recognized the human drafting gaps but found that the
current JSON artifact is “a static handoff, not an executable checker.” It also
found that a generic handoff may produce a “mechanical false-pass on field
presence” because the contract does not mechanically require actor-specific
individual-capacity units, determine qualified-immunity eligibility, or require
typed Monell paths.

For an `AuthorityProposition` containing only `826 F.3d at 284–86`, the
evaluator found that the production contract can establish only that a pinpoint
field is populated. It cannot resolve the verified authority unit, canonical
opinion, hash, or matching passage.

## Monell drafting

The evaluator honored the user's approval boundary and refused to draft the
three pending paths. It also refused the approved formal-policy path, treating
multiple employees' repeated “our policy” statements only as “record facts and
discovery leads” because a written policy and authorized decisionmaker were not
identified. The production skills provide no typed approved-path handoff for a
narrow direct-policy allegation with a specific information-and-belief basis.

## Monell planning

The evaluator kept the candidate paths separate, did not use post-event events
as pre-event notice, and did not turn FTO status into a freestanding Monell
path. It did not return stable typed path records, the four approved
recommendation states, or decision slots. It also introduced web authorities
without resolving them through the matter's verified authority store, opinion
artifacts, pinpoints, and exact source text.

## Required behavior change

The version-2 implementation must:

1. reject generic field-presence false passes;
2. return typed actor, qualified-immunity, and separate Monell-path records;
3. recommend without selecting or abandoning paths;
4. draft only litigation-principal-approved paths;
5. permit a supported direct-policy path without inventing a written policy or
   policymaker identity;
6. preserve post-event temporal limits and mechanism-versus-path boundaries;
7. read a supplied graph directly from disk and read-only; and
8. reject graph-used authority support unless the verified artifact, hash,
   pinpoint, and exact matching source passage resolve.
