# Retrospective

## Outcome

Issue 24 replaced three compositionally unsafe general complaint sources with
one install-local owner, two explicit fail-closed routes, and one bounded
machine-readable handoff. The false-arrest package now carries only its
substantive specialization delta while shared governance remains repeatable.

## What RED established

The umbrella-only package supplied a skeleton without the detailed count
contract. The general-only package supplied count rules without a whole-document
skeleton. The full stack supplied conflicting section orders, count granularity,
fair-warning triggers, and duplicate Monell/count ownership. Agents correctly
refused to invent or silently harmonize, which showed an ownership failure
rather than a model-discipline failure.

## What worked

- Separating the human contract from the mechanical JSON made the external
  checker boundary explicit without pretending that legal judgment is
  deterministic.
- Isolated package copies caught broken-link and fail-closed behavior that
  repository-root tests could have hidden.
- Fresh-context GREEN pressure found semantic drift that phrase-level tests did
  not: one extra human field, a stale umbrella reference description, and a
  competing count mnemonic.
- Keeping false-arrest doctrine in a named delta preserved its arrest-time
  offense, actor, seizure, warrant, incorporated-material, and compression rules
  without retaining a second general contract.
- Review mutations narrowed the final tests to realistic ownership failures
  rather than broad keyword bans.

## Review findings and corrections

The whole-story review found that the original fail-closed helper could accept
permission to draft because a separate non-invention prohibition remained, and
that the delta guard rejected only a complete duplicate field list. The final
test commit requires both fail-closed duties independently and rejects one
explicit canonical machine field in the delta. The scoped re-review was clean.

## Deviations

- Task 2 and Task 3 were committed separately rather than as one GREEN commit.
  This preserved the user-required sync-after-every-commit boundary and allowed
  the canonical owner to be independently reviewed before the specialization.
- The pressure review proposed encoding false-arrest, Monell, authority, and
  fair-warning judgments in JSON. That was rejected because the approved handoff
  is a bounded mechanical general interface and expressly excludes those legal
  judgments.
- Project 1 item creation remained unavailable because the authenticated GitHub
  token lacks `read:project`; branch work and issue creation were unaffected.

## Reusable lesson

For independently installed skills, one canonical owner is not enough by itself.
Every router must fail closed, every specialization must declare its delta
boundary, and fresh consumers must be able to distinguish a human function from
a machine field without silently completing either contract from general
knowledge.
