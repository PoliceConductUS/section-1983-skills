# Proposal: Build source-documented municipal Monell profiles

## Why

Municipal-liability work needs reusable institutional evidence organization, but
a profile must not become proof, governing law, or an automatic Monell theory.
Issue #31 needs a separate offline builder that preserves provenance,
counterevidence, uncertainty, and domain boundaries across ordinary input files.

## What changes

- Add `building-municipal-monell-profiles` with exact `municipality`,
  `department`, `source`, `policy-catalog`, `policy-assessment`, `case-record`,
  and `verified-authority` folders.
- Validate upstream policy and authority results, selected ordinary source
  bytes/YAML, input fingerprints, and cross-record identities.
- Organize proposed evidence and bounded questions under `Practice`,
  `Knowledge`, `Authority`, `Causation`, and `Recurrence` without element
  conclusions.
- Preserve entities, institutional events, notice/corrective chains,
  comparisons, contradictions, similarity features, favorable evidence,
  counterevidence, and explicit gaps.
- Return deterministic profile YAML, gap YAML, Markdown, and validation bytes
  for trusted-host publication.

## Capability

- `building-municipal-monell-profiles`

## Non-goals

- No package, graph, source collection, Monell-liability decision, legal advice,
  theory selection, allegation drafting, filing edit, or embedded real municipal
  conclusion.
