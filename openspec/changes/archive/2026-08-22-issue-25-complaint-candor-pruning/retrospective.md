# Retrospective

## Outcome

Issue 25 added four complaint-candor and pruning duties, then consolidated the
count and qualified-immunity completion fields into one canonical
claim–defendant–challenged-act checklist. The human contract and mechanical
handoff now expose the same tuple interface while `audit-authorities` retains
the detailed verification procedure.

## What RED established

Fresh consumers could volunteer an adverse merits assessment, expand a concise
fair-warning unit into a brief, retain uncertainty without a pleaded job, and
state an ambiguous incorporated-record fact without completing its effect on an
actually raised alternative offense. Later mutation work showed that apparently
green prose tests still accepted inline exceptions, one valid causal-first
formulation, human/JSON drift, and a duplicate differently named checklist.

## What worked

- Behavior-specific synthetic fixtures kept each regression discriminating.
- Direct semantic mutations found false greens that broad phrase-presence tests
  missed.
- Separating universal incompleteness from a qualified-immunity filing-critical
  GAP preserved the correct internal consequence without forcing an adverse
  concession into filed text.
- Adding stable machine identifiers to the human qualified-immunity list made
  drift visible without creating an executable legal-judgment checker.
- Keeping authority procedure in `audit-authorities` avoided a second audit
  owner while still making complaint completion fail closed.

## Review findings and corrections

The first whole-story review found under-discriminating fixture rules and test
coupling. Corrective review then found inline `unless` loopholes and a valid
Z2-first false positive. Consolidation review found a stale JSON handoff and a
test that collapsed universal and qualified-immunity failures. Final mutation
review found strategy-exception variants and a second-checklist escape. Each
accepted finding was captured as RED before its narrow correction; the final
review was clean.

## Deviations

- The canonical checklist refinement was added during final review after the
  user approved consolidating field names and fail-closed ownership. It remained
  within Issue 25 because it refined the same complaint-completion and bounded
  fair-warning contract.
- The JSON handoff changed despite the original plan's no-executable-checker
  boundary. The handoff remains non-executable; only its published tuple and
  field interface changed to prevent human/machine drift.
- More than one corrective review cycle was necessary because successive direct
  probes exposed load-bearing false greens. The user expressly directed that the
  known residual findings not be ignored.

## Reusable lesson

A canonical prose checklist is not singular merely because one heading has the
word “canonical.” Its human fields, machine identifiers, failure classes, and
ownership boundary must agree, and mutation tests must reject inline exceptions
and alternate owner headings.
