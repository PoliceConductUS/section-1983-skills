# Retrospective

## Outcome

The Monell planning and drafting skills now preserve proposition classification
from path planning through complaint integration and carry supported but
incomplete paths in a staged-development record. The contract keeps predicted
discovery from masquerading as present evidence while allowing narrow, source-
grounded inferences in complaint allegations.

## What RED established

The prior wording was directionally correct but not reliable under behavioral
pressure: two of five fresh baseline agents moved unavailable directives,
training materials, or complaint history into proposed complaint text. The first
structured validator also lacked proposition records, and its initial
implementation could crash on list-valued identifiers or silently accept
malformed bases.

The staged baseline also showed that correct refusal to plead a placeholder did
not reliably produce request-specific relevance, date triads, diligence,
deadline, evidence-threshold, risk, and amendment-standard fields.

## What worked

- Giving planning semantic ownership and drafting placement ownership avoided
  duplicating the classification decision.
- Stable proposition IDs made inference premises and placement checkable across
  the planning handoff and complaint delta.
- Pairing semantic pressure tests with structural validation covered both agent
  behavior and malformed machine records.
- Isolating each permanent regression prevented a generic missing-inventory
  finding from hiding a broken substantive rule.
- A fresh guided run exposed relative-deadline date invention that contract-only
  tests had missed.

## Review findings and corrections

Independent review drove the original proposition corrections and then exposed
an incomplete staged passing fixture, insufficient staged regression coverage,
and stale lifecycle artifacts. Later review rounds found multi-request and type
validation gaps, source-inventing relevance examples, JSON key-order and stable
request-identity bypasses, generic relevance in isolated regressions, and
permissive reassessment values. The staged fixture now uses source-aligned
examples and structured rules that validate every request member, stable IDs,
nonempty types, and exact mandatory gates. Final independent review found no
remaining Critical or Important findings.

## Delivery sequence

The issue, remote branch, and draft PR were not created before implementation
because the approval boundary initially blocked publication of the approved
legal-skill contract. After the user explicitly authorized commit and push, the
completed OpenSpec change was archived on its owning branch before publication.
Creating a GitHub issue or PR remains outside this delivery request.

## Reusable lesson

A three-class prose rule is not durable unless proposition identity, factual
basis, placement, and type constraints survive every handoff. Behavioral
regressions must also be isolated so one generic failure cannot make a broken
specific rule appear green. Relative procedural intervals must remain relative
until the controlling source and a source-backed as-of date support calculation.
